# Technical debt register

Every "known limitation", "not measured", "not solved" and negative consequence already
written down in this repository, collected in one place so that none of them can be
mistaken for an oversight — or for a solved problem.

**Nothing here is new.** Each row traces to a sentence that already exists in the file
named in *Source*; no debt was invented, and no closing date was invented either. Where a
source contradicts another source the row says so. `Recorded` is the date the source
document carries, not a deadline. `docs/architecture.md` carries no date, so rows that
rest on it say `undated`.

## Review cadence

* **Monthly.** Walk the table top to bottom; for each row confirm the cited sentence still
  exists and still says what the row says. A row whose source sentence changed is updated in
  the same commit as the source.
* **An item leaves this table only with a commit SHA that closes it.** Move the row to a
  `Closed` section with the SHA linked (`https://github.com/ozantosn24-ux/portable-ai-core/commit/<sha>`)
  and one line saying what evidence proves it closed — a test name, a measurement, a CI job.
  **Never delete a row silently.** A row deleted without a SHA is indistinguishable from a
  limitation that was quietly forgotten, which is the exact failure this file exists to prevent.
* **No closing dates are recorded here** because none exist in the sources. `Recorded` is
  provenance, not a deadline; `undated` means the source document carries no date.
* New debt enters the same way every existing row did: it must already be written down, with
  its consequence, in a README, ADR, drill record or measured command output. If it is not
  written anywhere else, write it there first, then add the row.
